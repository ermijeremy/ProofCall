Below is a **single implementation spec** both teams can work from. It follows the challenge requirement: beneficiary interviews must establish job-quality clauses conversationally, produce clause-level status/confidence, and aggregate worker-side evidence beside employer figures. 

# CallProof × TeleExpert — Hackathon Project Spec

## 1. Product

**CallProof** independently verifies employer-reported job outcomes by directly interviewing sampled beneficiaries through ordinary phone calls.

**TeleExpert** is the voice execution infrastructure.

```text
Employer data + Beneficiary list
              ↓
          CALLPROOF
 sampling → interview spec → prompt
              ↓
     POST TeleExpert /v1/calls
              ↓
          TELEEXPERT
     call → interview → transcript
              ↓
          CALLPROOF
 evidence → rules → comparison → aggregate
              ↓
           Dashboard
```

### Responsibility boundary

> **CallProof decides who to call, what must be established, and what the evidence means.**

> **TeleExpert conducts the phone conversation and returns the conversation evidence.**

---

# 2. CallProof Core Flow

```text
1. Admin imports employer report + beneficiary contacts

2. Admin triggers verification campaign

3. CallProof samples beneficiaries

4. For each beneficiary:
   generate TeleExpert interview prompt

5. CallProof calls:
   POST /v1/calls

6. Track TeleExpert call status

7. When completed:
   retrieve transcript/audio

8. Extract structured worker evidence

9. Run deterministic job-quality rules

10. Compare worker evidence with employer claims

11. Aggregate all workers

12. Update dashboard
```

The challenge specifically requires employer monitoring figures to be checked against direct worker evidence, including difficult cases such as contradictions, refusals, and under-15 respondents.

# 4. TeleExpert Request Generated by CallProof

For every sampled worker:

```http
POST /v1/calls
```

```json
{
  "phone_number": "+251...",
  "prompt": "<generated CallProof interview prompt>",
  "response_format": "both",
  "retries": 2,
  "retry_delay_seconds": 30
}
```

The generated prompt must tell TeleExpert to establish:

* consent;
* age;
* employment status;
* employment duration;
* usual weekly working hours;
* salary;
* training participation;
* forced-labour condition;
* discrimination;
* freedom of association;
* required improvement criteria.

It must additionally instruct:

```text
Speak naturally.
Do not reveal qualification thresholds.
Do not lead the respondent.
Clarify vague answers.
Do not invent missing facts.
Respect refusals.
Ask only necessary follow-ups.
Establish age early.
If age < 15, stop the normal interview.
```

The challenge defines the relevant good-job conditions, including age, hours/duration and labour-rights conditions.

```json
{

  "consent": true,

  "clauses": {
    "age": {
      "value": 19,
      "status": "MET",

    "employment_duration": {
      "value": null,
      "status": "UNCLEAR",

      "evidence": "I started after the rains."
    },

    "working_hours": {
      "value": 40,
      "status": "MET",
      "confidence": "HIGH"
    }
  },

  "overall_verdict": "UNCLEAR"
}
```

Internal states:

```text
MET
NOT_MET
UNCLEAR
REFUSED
NOT_ASKED
STOPPED
```

Do **not** reduce everything to true/false. This matches the evidence-led architecture in the existing plan.

# 6. AI vs Deterministic Logic

This separation is mandatory.

### LLM

```text
Transcript
→ extract facts
→ normalize vague responses
→ identify evidence
→ identify refusal/ambiguity
```

### Code

```text
facts
→ calculate values
→ apply thresholds
→ MET / NOT_MET / UNCLEAR
→ final job verdict
```

Example:

```text
Worker:
"I work five days, around eight hours each."

LLM:
days = 5
hours/day = 8

Code:
5 × 8 = 40 hours/week

Rule:
40 >= 20

→ MET
```

Do **not** ask the LLM directly whether somebody has a “good job.”

# 7. Required Hard Cases

### Refusal

```text
"I don't want to tell you my salary."

salary.status = REFUSED
```

Never substitute employer salary.

### Employer contradiction

```text
Employer:
currently employed = YES

Worker:
"I left two months ago."

→ MATERIAL CONTRADICTION
```

Do not decide who is lying.

### Under 15

```text
age = 14

→ interview stops
→ STOPPED
→ NOT COUNTED
→ safeguarding flag
```

### Ambiguous date

```text
"I started after the rains."

→ TeleExpert asks temporal follow-ups
→ if six-month threshold still cannot be established:
UNCLEAR
```

These cases are explicitly important in the challenge and current architecture.

# 12. TeleExpert — Features Required

TeleExpert team should focus only on making these reliable:

### Already implemented / required

* `POST /v1/calls`
* exactly one phone number/request
* `202 Accepted`
* queue when gateway busy
* outbound dialing
* `GET /v1/calls/{id}`
* remote cancellation
* retries on unanswered calls
* configurable retry count/delay
* transcript result
* audio result
* states:

  * `queued`
  * `dialing`
  * `retry_wait`
  * `in_progress`
  * `completed`
  * `failed`
  * `cancelled`

### Conversation requirements

* execute long/rich prompt reliably;
* natural interview rather than fixed questionnaire;
* Amharic voice conversation;
* English conversation;
* ask contextual follow-ups;
* handle vague responses;
* avoid leading questions when instructed;
* recognize refusal;
* establish age early;
* obey prompt instruction to terminate when age <15;
* avoid unnecessary/repeated questions;
* cleanly end interview;
* reliable complete transcript.

### Strongly useful if easy

* expose detected/used language;
* timestamps in transcript;
* clear failure reason;
* metadata passthrough such as `worker_id`;
* webhook/callback on completion.

### Do **not** spend hackathon time on

```text
billing
large-scale telecom infrastructure
full admin frontend
new campaign system
sampling
programme rules
aggregation
employer comparison
structured good-job verdicts
```

Those belong to CallProof.
